# Static scene descriptor inspection profile

`scene.json` associates declared static visual and collision components with one immutable asset manifest. Both source families use this contract after baking. Descriptor binding is a metadata inspection step: it verifies the descriptor's actual bytes and declared file references against the supplied manifest. It does not decode or activate the referenced GLBs.

The descriptor schema version is `1`. Its supported reader contract is exactly `2`, rather than a semantic-version comparison. A package requires `static-scene-package-v1` and the union of its available components' requirements. Existing online reader advertisements and production publication flows remain unchanged; this module does not advertise support or connect a new client activation path.

```json
{
  "schemaVersion": 1,
  "set": "zone/authored",
  "zone": "authored",
  "scope": "declared-static-inspection-v1",
  "coordinateProfile": "eqoxide-static-y-up-v1",
  "unitScale": 1,
  "bakeRevision": "aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa",
  "requirements": {
    "reader_version": 2,
    "capabilities": ["static-collision-triangles-v1", "static-scene-package-v1", "static-visual-v1"]
  },
  "requiredOperations": [],
  "components": {
    "visual": {
      "availability": "available",
      "scope": "declared-static-visual-scene-v1",
      "file": {
        "path": "visual.glb",
        "blake3": "bbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbbb",
        "size": 2048
      },
      "requirements": {"reader_version": 2, "capabilities": ["static-visual-v1"]}
    },
    "collision": {
      "availability": "available-empty",
      "scope": "declared-static-triangle-candidates-v1",
      "file": {
        "path": "collision.glb",
        "blake3": "cccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccccc",
        "size": 584
      },
      "requirements": {"reader_version": 2, "capabilities": ["static-collision-triangles-v1"]},
      "queryPolicy": "inspection-segment-front-v1"
    }
  }
}
```

The hashes and sizes above illustrate the schema; generate actual values from the output bytes. `bakeRevision` identifies normalized bake input and policy, precomputed before component serialization. It is neither a hash of this descriptor nor the manifest revision, so there is no self-reference. Requirements retain the existing `reader_version` spelling; the descriptor's own fields use camelCase.

Both role records are mandatory. Visual availability is `not-extracted`, `unsupported` or `available`. Collision adds `available-empty`. Unavailable records contain only `availability`; stray file, scope, requirements or policy fields refuse. Known-empty collision references a real positive-size GLB and describes only the declared static triangle candidate scope. It says nothing about the world being empty, dynamic objects, regions or query results. Both roles may be unavailable; that package contains only `scene.json` and requires only the package capability. Missing roles or a `missing` availability literal are malformed.

Available visual requirements are exactly reader `2`, `static-visual-v1`, and optionally `vertex-rgba-v1`. Available collision requirements are exactly reader `2`, mandatory `static-collision-triangles-v1`, and optionally `eqoxide-source-query-frames-preserved-v1`. The optional capability explicitly declares preserved supplied source collision query frames under the [collision contract](static-collision-contract.md); it is an eqoxide assertion, not universal EQ/RoF2 units, game identity, importer provenance verification, implemented query support or native query agreement. Unknown source frames stay unspecified. Available-empty collision carries the same declaration rules. Collision declarations cannot occur on visual or unavailable roles. Component capability order is set-like, with duplicates refused. Its declared policy is `inspection-segment-front-v1` or `inspection-segment-both-v1`. Recognizing either policy does not implement segment queries. Root capabilities must be the sorted unique union, and `requiredOperations` must be present and empty. Unknown fields, duplicate decoded keys (including escaped equivalents), duplicate component/root capabilities, unsupported scopes/profiles, fractional integer tokens and unsupported versions refuse.

The zone follows the existing bounded lowercase token grammar: 1–128 ASCII characters, an initial lowercase letter or digit, and subsequent lowercase letters, digits, `.`, `_` or `-`. `set` must equal `zone/<zone>`. Referenced paths follow the existing manifest relative-path grammar, are distinct, and cannot be `scene.json`. Hashes are 64 lowercase hexadecimal BLAKE3 digits. Size is a positive unsigned integer within the component budget. These path checks are protocol checks, not filesystem or URL resolution guarantees.

`SceneFile::from_bytes` checks its byte limit before hashing caller-supplied generated bytes. It does not parse those bytes: even a hash-matched non-GLB can bind as metadata. `SceneDescriptor::new` derives the identity fields and requirement union; mutable DTOs are revalidated at encoding and binding. Encoding bounds JSON while writing, and decoding checks encoded size before strict typed deserialization with normal recursion protection.

| Default limit | Value | Work bounded |
| --- | ---: | --- |
| `max_json_bytes` | 65,536 | Encoded descriptor input and serialization |
| `max_component_bytes` | 134,217,728 | Caller bytes hashed and declared component size |
| `max_manifest_files` | 1,024 | File-entry traversal before manifest validation |
| `max_chunk_references` | 65,536 | Aggregate chunk-reference traversal before canonical serialization |

The initial inspection profile is closed: its manifest contains exactly `scene.json` plus the available component references, at most three files. Extra files require a reviewed extension. File and aggregate chunk caps are checked before the existing manifest validator serializes canonical identity. These limits bound this API's work; a caller must also bound any file/network ingestion and preallocated collections.

`bind_scene_descriptor_to_manifest` requires the requested zone, a valid manifest digest/revision, exact membership, the actual descriptor-byte BLAKE3 and size, matching component file hashes/sizes, and the normalized manifest capability union at reader `2`. Existing manifest capability ordering and duplicates normalize according to its established identity rules. The returned `DescriptorManifestBinding` has read-only accessors for decoded metadata, manifest revision and descriptor digest. No CAS or filesystem reads occur during binding. A valid explicitly supplied older manifest remains valid metadata inspection; current/latest world or session freshness is not detectable here.

`write_scene_descriptor` atomically replaces one descriptor using the existing staged-file publisher (mode `0644` on Unix). Validation or serialization failure preserves an existing destination, and replacement failure cleans the staging file. This is not a transaction across components and manifest, nor a claim of crash-durable directory publication.

Full activation remains a separate gate: verify actual component/CAS bytes, both GLB headers, geometry, profiles, bake identities and requirements before committing one runtime snapshot. Coverage declarations cannot prove completeness of source extraction. Activation and query leases must compare expected immutable revision and world generation; a failed new-zone activation must never answer queries from an old snapshot. Geometry decoding, gameplay collision, navigation and query operations are outside this descriptor unit.

For an authored producer example, run `cargo run --locked --example static_scene_descriptor_fixture -- OUTPUT_DIRECTORY`. It uses the real GLB writers, hashes their outputs, writes the descriptor and an explicit local CAS/manifest, then binds metadata and checks deliberately corrupted declarations. Its JSON summary distinguishes binding from component decoding, chunk-content verification, segment queries and runtime activation. It uses no native input and is not a real-zone or game acceptance test.

The authored `static_scene_descriptor_fixture OUTPUT_DIRECTORY [--declare-preserved-source-query-frames]` tool binds actual generated components through the producer APIs. The selected declaration contributes to its bake revision; default mode remains unspecified. Its report keeps segment queries and runtime activation false. The retired `static-collision-query-unit-frames-v1` capability is refused on components and at the root even with matching references or hashes; `--canonical-query-units` is also refused. The example hashes its own source bytes, so the naming update intentionally changes default-mode bake revisions and generated component/package bytes, including its visual GLB. This is separate from the unchanged unspecified declaration behavior and geometry.
