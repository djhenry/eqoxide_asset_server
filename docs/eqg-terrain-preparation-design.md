# Tiled terrain: native initial-load preparation candidate

This proposal follows [issue #100](https://github.com/djhenry/eqoxide_asset_server/issues/100) within [M4](eqg-zone-support-project-plan.md#m4--eqtzpdat-terrain-and-materials). It specifies the next proof target, not an implemented or certified terrain bake. Source-specific preparation stays in the asset server; visual and collision outputs continue to use the common GLB contracts.

## Source findings and evidence limits

Raw format decoding is separate from scene preparation. The proposed library readers for [EQTZP metadata](https://github.com/djhenry/libeq/pull/18) and [packed DAT v20](https://github.com/djhenry/libeq/pull/20) preserve source bytes and record boundaries. They do not establish a prepared surface, tile membership, resource precedence or gameplay collision. Neither contribution is treated here as merged or as a producer dependency update. A later proof must bind its selected reader revision and exact fixture bytes, including expected record boundaries. A reader change invalidates the affected acceptance evidence until those fixtures are rechecked. If a required reader or framing rule is unavailable or unsupported, refuse that profile; do not silently substitute another reader, default metadata or a partial decode.

The following preparation facts were checked against the native RoF2 client through source inspection. They are not captured native-run results or certification of a whole tile set. Detailed provenance is retained privately; public documentation does not reproduce internal symbols, addresses, tooling paths, excerpts or game assets. The independent native-output fixtures required for admission are still outstanding:

| Boundary | Established behavior | What does not follow |
|---|---|---|
| Segment-collision provider | Supplies working heights and current quad flags | Untouched DAT heights and stored diagonal bits are not a sufficient preparation specification |
| Load traversal | Creates concrete tiles, then performs an ascending-x/ascending-y seam pass followed by an update pass in that order | Sorting an arbitrary selected subset is not proof of matching loader membership |
| Seam operation | Copies an available east neighbor's working first column to the current last column, then an available north neighbor's working first row to the current last row; absent lookups are skipped | A direct northeast copy, dense rectangular membership, averaging or universal raw-height corner ownership does not follow |
| Hierarchical refinement | Flags or child requests can force splitting. Otherwise, for finite comparison operands, the error test requests a split only when deviation exceeds tolerance; equality alone does not request one | Zero tolerance does not guarantee a fully split topology |
| Index representation | Full-grid indexing shares the same refinement passes as compact indexing | Full-grid indexing is not a maximum-detail override |
| Initial controls | Ordinary project loading explicitly reinitializes global tolerance to `1.0` before loading tiles; fresh tile override state selects that global value | Transitive resource-callback effects and later quality-setting behavior remain unverified |

Emission scans internal nodes in ascending index order, processing the first tree and then the second at each index. A split node emits a retained unsplit odd child before a retained unsplit even child, in each child's stored corner order. Unsplit internal nodes still write working midpoint heights even when a coarser ancestor covers them. Replacing that scan with recursive traversal or skipping covered descendants is not established as equivalent.

Preparation can interpolate unused working midpoint heights and regenerate diagonal bits from emitted triangles. Different raw and working buffers do not by themselves prove different final surfaces: interpolated points might lie on the same emitted surface. Exact equivalence remains unproved.

Confirmed preparation paths include the initial load and a raw-height reset/edit path. Camera-, frame- or gameplay-triggered changes have not been established. Mutable buffers and an unrestricted tolerance setter are not sufficient evidence that the client needs runtime terrain preparation. A faithful fixed load snapshot may satisfy the intended bake architecture.

## Candidate to prove

The ordinary native packed-load path derives its DAT request from the parsed project `NAME` plus `.dat`, rather than substituting the descriptor stem. Namespace selection, loose/archive precedence and malformed-name admission remain separate producer policies; a resource-name observation does not establish those policies.

Target the actual initial-load preparation first, without forcing detail or changing authored flags:

1. Admit only a tile set whose concrete native membership and coordinate rules have been established for the profile, with bounded counts and explicit selected-resource identities. Those rules remain a proof gate: decoding every counted DAT record or sorting an arbitrary subset does not by itself establish native membership. Start with packed DAT v20 and `q = 32` as the limited geometry proof target; the broader dimensions accepted by the raw parser do not imply geometry-profile support.
2. Initialize working heights from raw heights and preserve initial quad flags. Distinguish a genuinely absent native neighbor from unavailable required input. If a tile/resource required by the admitted membership is missing, truncated, ambiguous or unsupported, refuse the whole geometry bake without partial publication. An unresolved membership decision also prevents profile admission. Do not impose a dense rectangle or require all east/north/northeast neighbors: the native seam operation skips absent lookups.
3. Reproduce the complete ordered seam pass before the ordered preparation pass with self/east/north/northeast contexts, cached split state and dependency propagation. Copy east first and north second from the donors' working buffers at the instant of each read. With grid indexing `[y][x]` and `q = 32`, north writes the final self corner `[q][q]` from its `[0][q]` if present; otherwise an east copy leaves its `[q][0]` there, or the prior self corner remains if neither is present. There is no separate northeast fetch in this seam operation. Under distinct, non-overflowing coordinates, nonaliasing tile views and no intervening mutation, the ascending-X/ascending-Y schedule visits those donors later; this is not universal raw-height ownership. Native corner fixtures must bind the actual donor contents, scheduling and relevant callbacks.
4. Treat `1.0` as the verified outer-load reset value, not a certified effective tolerance at comparison time. A profile may use it as the effective value only after proving that intervening callbacks, providers or quality actions preserve it for the admitted configuration. Otherwise establish the actual effective controls and their scope, or refuse the unsupported profile. Constructor defaults and the reset alone do not close this gate.
5. Reproduce the hierarchy, emission, working-height stores and diagonal regeneration with an explicit numerical contract. Require bit-exact expected working-height stores, emitted index/corner order and flags against independently captured native outputs for the admitted profile, including threshold ties and nearby rounding cases. Bind the effective arithmetic controls and store boundaries; do not replace wide intermediates with a sequence of `f32` operations. Capture the render and prepared collision streams and compare their surfaces separately.
6. Convert verified results into the common coordinate basis once while preserving explicitly identified source query-unit frames, component roles and visual/collision pairing. A frame declaration identifies the supplied units; it does not certify universal EverQuest units or native-query agreement. Separate geometry is permitted if the proof requires it; sharing geometry requires evidence.

This candidate neither selects a deliberately forced full-detail policy nor introduces a runtime client capability. Source-specific hierarchy and seam rules belong in the bake. Future enhanced legacy content may use any resulting source-independent capability under the same contract.

## Proof required before a geometry bake

- Verify exact hierarchy neighbor links, emitted corner ordering, holes and dependency propagation, including missing outer neighbors and repeated preparation state.
- Verify loader tile membership, source-order versus preparation-order rules, duplicate coordinates and incomplete input refusal. Establish the geometry dimension domain rather than inferring it from the raw parser. Distinguish admitted absent neighbors from missing required records/resources; uncertainty must refuse admission rather than manufacture boundary heights or a partial surface.
- Freeze asymmetric east/north/northeast corner fixtures, including east-only, north-only, neither and differing donor borders. Verify the second copy's actual donor contents and the full-pass schedule; a geographic corner-owner rule or an isolated seam-function test is not enough.
- Verify floating-point evaluation, ambient precision/rounding controls and stored-value boundaries. The error calculation has no intermediate `f32` store between endpoint addition, halving, midpoint subtraction and comparison. Wider operations may still round at their active precision; the missing binary32 store is not an exact-real arithmetic promise. Finite `f32` inputs therefore do not establish that rounding each operation to `f32` is equivalent. Bind the actual arithmetic state before certifying threshold behavior.
- Verify remaining intervening callback/quality effects and mode-specific height-buffer selection. The explicit load-time reset does not certify a universal active profile or rule out later changes.
- Freeze independent expected prepared heights, indices and flags for asymmetric noncoplanar fixtures, exact-threshold ties, holes, forced-detail source bits, mismatched shared borders and corner cases. Include resource/work limits and explicit unsupported inputs. Record exact input bytes or their reproducible identity, selected reader revision, control/configuration capture and bit-exact expected outputs. A mathematical arithmetic oracle or a passing synthetic model alone is not native-output acceptance.
- Compare render and collision surfaces and preserve any verified difference in their respective common components. Test winding after basis conversion; decoding success is not a query or movement certificate.

A next implementation plan should name the complete preparation profile, its input membership, numerical rules and independent oracle. It should not substitute a uniform diagonal, shortest-edge heuristic, raw stored diagonal or altered tolerance when proof is missing. Native behavior for unverified inputs remains unavailable, rather than becoming a successful-looking guessed surface.

## Scope and consequences

No new GLB schema, manifest requirement, producer route, dependency pin, material approximation, collision operation or gameplay activation is proposed here. Existing [visual](static-visual-contract.md) and [collision](static-collision-contract.md) contracts remain the output boundary. Reader/capability requirements must be reviewed if a later implementation actually adds one.

The additional cost is bake-side hierarchy, neighbor-state and numerical verification. Runtime terrain work is only a contingency if a required surface-changing runtime dependency is later demonstrated. A deliberately forced-detail policy or a source-height inspection approximation would be a separate fidelity choice to explain before adoption. The material/lighting scope decision remains independent.

This proposal enables neither production publication nor a native-query certificate. Raw readers and a plausible visual preview do not close M4; representative source, geometry, delivery and gameplay acceptance remain separate gates.
